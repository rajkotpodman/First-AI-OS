# Security Policy & Defensive Specifications (`SECURITY.md`)

First AI OS executes code generated by artificial intelligence models and user prompts. Because autonomous agents possess the ability to write code, install packages, and invoke shell utilities, security is engineered into the core architecture through multi-layered defensive rings.

## 2. Defensive Security Architecture

First AI OS enforces defensive isolation across three distinct tiers:

```text
 ┌────────────────────────────────────────────────────────────────────────┐
 │ TIER 1: STATIC COMMAND GUARDRAILS (security_daemon.py)                 │
 │ • Destructive regex filter blocks: rm -rf /, mkfs, dd to raw drives    │
 │ • System partition protection: /boot, /sys, /dev block write locks     │
 └──────────────────────────────────┬─────────────────────────────────────┘
                                    │ Passed Inspection
 ┌──────────────────────────────────▼─────────────────────────────────────┐
 │ TIER 2: CONTAINER RUNTIME SANDBOXING (sandbox_runner.py)               │
 │ • All untrusted / generated code runs inside disposable containers     │
 │ • Strict Linux Capabilities Drop: --cap-drop=ALL                       │
 │ • Seccomp Syscall Filtering (configs/seccomp_profile.json)             │
 │ • Strict Resource Quotas: 2 Cores, 2 GB RAM, 256 Max PIDs, Read-Only / │
 └──────────────────────────────────┬─────────────────────────────────────┘
                                    │ Signed Audit Record
 ┌──────────────────────────────────▼─────────────────────────────────────┐
 │ TIER 3: IMMUTABLE AUDIT TRAIL (/var/log/ai_security_audit.json)        │
 │ • Every command execution, timestamp, user, PID, and exit code         │
 │ • Cryptographic SHA-256 state seal on system shutdown                  │
 └────────────────────────────────────────────────────────────────────────┘
```

## 3. Seccomp-BPF Syscall Filter Details

When AI OS runs code inside `sandbox_runner.py`, it enforces a strict Seccomp syscall filter defined in [`configs/seccomp_profile.json`](file:///e:/AI%20OS/configs/seccomp_profile.json):

### Blocked Syscalls:
- **Kernel Module Operations:** `init_module`, `finit_module`, `delete_module`.
- **System Reboot & Shutdown:** `reboot`, `kexec_load`, `kexec_file_load`.
- **Hardware & Device Probing:** `iopl`, `ioperm`.
- **Filesystem Mounts:** `mount`, `umount2`, `pivot_root`.
- **Ptrace & Debug Inspection:** `ptrace`, `process_vm_readv`, `process_vm_writev`.
- **Network Interface Manipulation:** `bpf`, `setns`.

### Permitted Syscalls:
Standard computational, POSIX file I/O, IPC socket operations, memory allocation (`mmap`, `brk`), and basic threading (`clone3`, `futex`).

## 4. Reporting a Security Vulnerability

If you discover a security vulnerability or bypass in First AI OS (such as a command guardrail bypass, seccomp escape, or privilege escalation):

1. **Do NOT report security vulnerabilities via public GitHub Issues.**
2. Send an email with a detailed Proof of Concept (PoC) to:
   - **Security Contact:** `athanu000@gmail.com`
3. Include the following details:
   - Subsystem affected (e.g., `sandbox_runner.py`, `security_daemon.py`, or `build_base_os.sh`).
   - Step-by-step reproduction instructions.
   - Potential impact (e.g., container breakout, unauthorized file modification).
   - Any suggested mitigations or patches.

### Vulnerability Disclosure Response SLAs:
- **Initial Response:** Within 48 hours of receipt.
- **Triage & Assessment:** Within 5 business days.
- **Fix & Public Advisory:** Within 30 days (coordinated disclosure).

Thank you for helping keep First AI OS and its users secure!
